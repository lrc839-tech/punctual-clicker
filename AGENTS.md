# Installed app identity

- This project has repeatedly lost Accessibility grants after ad-hoc rebuilds. A fixed bundle ID and path alone do not preserve a TCC grant. Check `codesign --display --requirements -`.
- Install through `build.sh --install`. Do not manually replace the canonical installed app with `ditto`, a CI artifact, or a new ad-hoc build to bypass the identity compatibility check.
- Existing installs must pass `scripts/check-update-identity.sh` before replacement. Never weaken the designated requirement to the identifier alone.
- If a persistent signing identity is configured, reuse the same identity and compatible requirement. Missing or unavailable identity is an installation blocker; do not silently fall back to ad-hoc and overwrite the authorized app.
- Local builds automatically load the public identity fingerprint from `~/Library/Application Support/PunctualClicker/Signing/local-identity.sha1`; the private key remains in the login keychain. The user explicitly approved creating this dedicated local identity on 2026-10-29. Reuse it; do not create or rotate another certificate during routine updates.
- Public packaging calls `build.sh --distribution`, which excludes the local development identity; never replace this Mac's local-signed installed app with a public ad-hoc artifact. A new public release is a separate distribution channel.
- A deliberate identity migration requires the user's approval and `--allow-identity-change`. Explain that one new authorization is necessary. Creating a private signing key, adding keychain trust, and changing privacy grants are separate actions; do not infer permission to do them merely from a build request.
- Local self-signed certificates are for internal development, not the public Developer ID release channel. Keep all signing private keys outside the repository and release assets.
- Confirm permission retention by authorizing build A and replacing it with a different, identity-compatible build B at the canonical path, then checking the current process and a safe receiver. A requirements comparison alone does not prove live TCC retention.
- Verified on this Mac on 2026-10-29: build 10 (A) and build 11 (B) have different CDHashes and the same certificate-backed DR. Each received 30/30 real clicks in its own receiver; B retained Accessibility without changing privacy settings. Current canonical install is 0.5.0 (11), local-development signed. Evidence is in `Reports/stable-signing-retention-20261029.json` (local, ignored). This does not establish Screen Recording retention, other-Mac behavior, or ticket-purchase success. Preserve this fixed identity and use build numbers at least 11 for subsequent local updates.
